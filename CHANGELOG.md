# Changelog

Each version is published as one commit on top of the version before it, so this file is the record of what changed inside each one.

## 2.0.0

The image is rebuilt around ocserv 1.6.0. Every build compiles the newest stable ocserv release from its tarball after checking the tarball's signature against the maintainer's pinned key, in a multi-stage Alpine 3.24 build pinned by digest, with stack protection, fortified functions, full RELRO and position-independent code. The build patches ocserv's worker to size its signal stack from the kernel's reported minimum instead of the C library's fixed `SIGSTKSZ`, which some x86-64 hosts refuse, stopping every worker at start with `sigaltstack: Out of memory`; the build stops if the patch no longer applies. The runtime image holds ocserv and the admin panel, the libraries they link against, the firewall tools, certtool, bash and tini, and is 45.2 MB for linux/amd64.

The container no longer needs `--privileged`. It runs read-only with all capabilities dropped but the ones it uses and with `no-new-privileges`, and it checks the tun device, IPv4 forwarding and the firewall at start, stopping with the flag to add when one is missing.

The configuration is rendered from environment variables at every start instead of edited in place. Every ocserv option can be set: named variables cover the common settings and limits with moderate defaults (128 clients, 4 sessions per user), `OCSERV_CONF_<OPTION>` sets any other option, and `/config/ocserv-extra.conf` takes an ocserv.conf fragment. Invalid values stop the container with a message naming the variable. `POWER_USER=true` still uses `/config/ocserv.conf` as it stands, and writes it once from the environment when it is missing.

Traffic stays in the tunnel: full-tunnel clients get an IPv6 address and route through the VPN when the container can carry IPv6, so native IPv6 cannot bypass it, and DNS goes through the tunnel in both tunnel modes. The default DNS servers are Quad9 and Cloudflare. A firewall loaded into the container's network namespace (nftables, with legacy iptables where nf_tables is missing) forwards only client traffic and its replies, isolates clients from each other, closes the container to them except for ping, clamps TCP MSS and translates client addresses. Split-include mode restricts each client to its routes.

TLS is limited to versions 1.3 and 1.2 with ECDHE key exchange and AEAD ciphers, and the UDP channel inherits the same ciphers. Compression is compiled in and off. The image adds camouflage, time-based one-time passwords, the PROXY protocol, security headers, a private CA and server certificate created on first start and renewed with the same key, the server key's pin in the start-up log, and ocserv's own log on standard output.

Upgrades keep users, certificates and keys. Files the previous image copied into `/config` are recognized by hash: untouched ones are renamed `*.legacy`, and a hand-edited `ocserv.conf` is used as the whole configuration with a warning. The default limit of 4 sessions per user and the isolation of clients from each other are new defaults; `MAX_SAME_CLIENTS` and `CLIENT_TO_CLIENT` restore the previous behavior.

An optional web admin panel, off unless `PANEL_ENABLED=true`, runs beside ocserv as two processes: a root helper that holds the admin accounts, the audit log and every change, and a web process without capabilities that serves the pages over HTTPS from its own certificate and reaches the helper through a socket only its account can use. Admins are owners, operators or viewers. Each signs in with a password and, from outside `PANEL_LAN_NETWORKS`, a code from an authenticator app or a passkey; the first admin's one-time password must be replaced at the first sign-in. The pages are rendered on the server with one small script, in light and dark themes, and every form is checked for its CSRF token and its origin.

From the panel, admins manage VPN users with a printable onboarding kit, groups, per-user and per-group settings, sessions, bans and a firewall blocklist, country rules with DB-IP Lite or MaxMind GeoLite2, site-to-site rules, the server's settings, and client certificates from a client CA that signs nothing else. Alerts reach each admin through ntfy, Telegram, a webhook or email. Live events show connections, refused sign-ins and bans as they happen, and the audit log records every sign-in and change. Location checks, off until turned on, score each VPN and panel sign-in from 0 to 100 against the places, networks and habits the account showed before, alert on an unusual one and refuse an implausible one once the account is learned; a check that cannot run lets the sign-in through. An optional user portal lets VPN users see how to connect, change their password, set up their authenticator app and end their own sessions.

Images are published for linux/amd64, linux/arm64 and linux/arm/v7 to Docker Hub and GitHub Container Registry, with an SBOM and provenance, whenever ocserv releases a new version and every week. `tests/run.sh` checks the entrypoint modules and the running image, and the documentation is a new wiki.
